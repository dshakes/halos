## Request path inside halo-proxy

<img class="diagram dark:sl-hidden" src="/halos/diagrams/lld-request-path-light.svg" alt="Twelve stages of halo-proxy ServeHTTP in order, with the status each rejecting stage returns: snapshot (503), identity (401), body bound (413), kill list, decision (400/404), route order, attempts and translation (502), header hygiene, shadow mirror, failover (503), streaming, deferred metrics." width="760" />
<img class="diagram light:sl-hidden" src="/halos/diagrams/lld-request-path-dark.svg" alt="Twelve stages of halo-proxy ServeHTTP in order, with the status each rejecting stage returns: snapshot (503), identity (401), body bound (413), kill list, decision (400/404), route order, attempts and translation (502), header hygiene, shadow mirror, failover (503), streaming, deferred metrics." width="760" />

Everything below runs inside `Proxy.ServeHTTP` ([`cmd/halo-proxy/proxy.go:171-353`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L171-L353)). The reverse proxy is built once, in `newProxy` ([`cmd/halo-proxy/proxy.go:65-109`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L65-L109)).

1. **Snapshot.** `p.snap.Get()` returns the compiled policy and reloads it when the file changes ([`internal/gateway/snapshot.go:32-61`](https://github.com/dshakes/halos/blob/main/internal/gateway/snapshot.go#L32-L61)). If the policy is missing and there is no `--next-hop` or `--default-upstream`, the answer is `503 policy_unavailable` ([`cmd/halo-proxy/proxy.go:214-221`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L214-L221)).
2. **Identity.** `authenticate` picks a verifier from the configured mode ([`internal/identity/resolve.go:68-83`](https://github.com/dshakes/halos/blob/main/internal/identity/resolve.go#L68-L83)):
   - **OIDC JWT:** go-oidc against the issuer's JWKS ([`internal/identity/oidc.go:71-91`](https://github.com/dshakes/halos/blob/main/internal/identity/oidc.go#L71-L91)).
   - **Trusted header:** honoured only when the TCP peer is in the trusted proxy CIDRs ([`internal/identity/identity.go:72-100`](https://github.com/dshakes/halos/blob/main/internal/identity/identity.go#L72-L100)).
   - **None.**

   Gemini CLI's `x-goog-api-key` is verified like a bearer token. A failure is `401` with `WWW-Authenticate`, an identity header sent twice is `400`, and `--allow-anonymous` downgrades a failure to default routing ([`cmd/halo-proxy/proxy.go:357-395`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L357-L395)).
3. **Body bound.** Every body is wrapped in `MaxBytesReader`. Model calls are read in full for inspection, and oversize is a hard `413` ([`cmd/halo-proxy/proxy.go:228-250`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L228-L250)). The default limit is 32 MiB ([`cmd/halo-proxy/config.go:97-112`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/config.go#L97-L112)).
4. **Kill list.** `KillSwitch.Apply` returns a copy of the policy with every killed experiment set to `paused` and every killed toggle removed. Killed experiments therefore route to control and mirror nothing ([`internal/gateway/killswitch.go:280-305`](https://github.com/dshakes/halos/blob/main/internal/gateway/killswitch.go#L280-L305)). The list is polled every 10 s by default and accepted only if its ed25519 signature verifies, it is at most 10 minutes old, and it is newer than the current list ([`internal/gateway/killswitch.go:60-82`](https://github.com/dshakes/halos/blob/main/internal/gateway/killswitch.go#L60-L82), [`internal/gateway/killswitch.go:159-245`](https://github.com/dshakes/halos/blob/main/internal/gateway/killswitch.go#L159-L245)).
5. **Decision.** `PrepareVerified` collects every client `x-halo-*` header name for removal, builds the request info from the verified subject only, and calls `Decide` ([`internal/gateway/prepare.go:135-171`](https://github.com/dshakes/halos/blob/main/internal/gateway/prepare.go#L135-L171)). `Decide` resolves the subject's ring. It then applies a traffic toggle's route for the alias ([`internal/gateway/toggles.go:12-26`](https://github.com/dshakes/halos/blob/main/internal/gateway/toggles.go#L12-L26)), and the first traffic-axis experiment by name whose variant routes this alias. A client-axis experiment is attributed but never routes ([`internal/gateway/decision.go:60-144`](https://github.com/dshakes/halos/blob/main/internal/gateway/decision.go#L60-L144)). `admit` enforces the model allowlist: `404` for unknown paths, `400` for models that are not a policy alias ([`internal/gateway/prepare.go:99-128`](https://github.com/dshakes/halos/blob/main/internal/gateway/prepare.go#L99-L128)). The request body is rewritten to the upstream model.
6. **Route order.** `RouteOrder` sorts targets into priority tiers. Within a tier the weighted pick goes first, chosen by `assign.Pick` over the sticky key `user + session` ([`internal/gateway/route.go:14-58`](https://github.com/dshakes/halos/blob/main/internal/gateway/route.go#L14-L58), [`internal/assign/assign.go:28-53`](https://github.com/dshakes/halos/blob/main/internal/assign/assign.go#L28-L53)). `assign` is the single source of hashing (AGENTS.md invariant 3).
7. **Attempts.** `buildAttempts` drops a target, with a log line, when:
   - its upstream kind cannot serve the client's wire protocol
   - its URL fails `CheckURL`
   - it would SigV4-sign for a host that is neither AWS nor in `signHosts`
   - translation fails in `BuildOutbound`

   ([`cmd/halo-proxy/route.go:48-97`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/route.go#L48-L97), [`internal/gateway/upstreamauth/apikey.go:99-121`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/apikey.go#L99-L121), [`internal/gateway/translate.go:39-81`](https://github.com/dshakes/halos/blob/main/internal/gateway/translate.go#L39-L81)). If no target is left, the answer is `502 bad_upstream` ([`cmd/halo-proxy/proxy.go:268-276`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L268-L276)).
8. **Header hygiene.** Hygiene runs after the decision. That is safe because the decision never read client `x-halo-*` headers.
   - The client `x-halo-*` headers and the identity and groups headers are deleted.
   - The gateway's own `x-halo-ring|release|experiment|variant` are stamped.
   - Client credentials are stripped unless `--forward-auth` is set ([`cmd/halo-proxy/proxy.go:309-343`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L309-L343), [`internal/gateway/upstreamauth/apikey.go:47-51`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/apikey.go#L47-L51)).
9. **Mirror.** For shadow experiments, `shadow.Jobs` builds first-turn jobs that carry only allowlisted headers, and the mirror queues them asynchronously ([`cmd/halo-proxy/proxy.go:400-407`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L400-L407), [`internal/shadow/mirror.go:130-150`](https://github.com/dshakes/halos/blob/main/internal/shadow/mirror.go#L130-L150)).
10. **Failover.** `routeTransport` walks the attempts ([`cmd/halo-proxy/route.go:105-167`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/route.go#L105-L167)):
    - At most 3 attempts by default.
    - A target whose breaker is open is skipped. With more than one target, the breaker opens after 5 consecutive failures and allows one half-open probe after 30 s ([`internal/gateway/breaker.go:46-92`](https://github.com/dshakes/halos/blob/main/internal/gateway/breaker.go#L46-L92)).
    - A connect error, a 5xx or a 429 moves to the next target.
    - Retries happen only before any byte reaches the client.

    Each attempt in `try` installs that target's own credential ([`cmd/halo-proxy/route.go:178-253`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/route.go#L178-L253)):
    - Vertex: a metadata-server or service-account token ([`internal/gateway/upstreamauth/vertex.go:205-214`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/vertex.go#L205-L214)).
    - API-key kinds: the key from the gateway's environment ([`internal/gateway/upstreamauth/apikey.go:55-71`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/apikey.go#L55-L71)).
    - Bedrock: SigV4 in the transport ([`internal/gateway/upstreamauth/bedrock.go:139-194`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/bedrock.go#L139-L194), [`internal/gateway/upstreamauth/bedrock.go:206-208`](https://github.com/dshakes/halos/blob/main/internal/gateway/upstreamauth/bedrock.go#L206-L208)).

    If every target fails, the answer is `503 no_available_target` ([`cmd/halo-proxy/proxy.go:122-140`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L122-L140)).
11. **Stream.** `FlushInterval: -1` flushes every write ([`cmd/halo-proxy/proxy.go:95-107`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L95-L107)). A Bedrock event stream is converted to SSE when the client spoke the Anthropic protocol ([`cmd/halo-proxy/route.go:221-226`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/route.go#L221-L226), [`internal/gateway/eventstream.go:18-20`](https://github.com/dshakes/halos/blob/main/internal/gateway/eventstream.go#L18-L20)).
12. **Deferred metrics.** A `defer` records the request after the response completes ([`cmd/halo-proxy/proxy.go:178-212`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L178-L212)):
    - `halo.gateway.requests` and `halo.gateway.latency_ms`, sent over OTLP/HTTP to the collector's gateway receiver. The unit is the verified subject, never a client header ([`cmd/halo-proxy/proxy.go:256-262`](https://github.com/dshakes/halos/blob/main/cmd/halo-proxy/proxy.go#L256-L262), [`internal/telemetry/gwmetrics/gwmetrics.go:192-218`](https://github.com/dshakes/halos/blob/main/internal/telemetry/gwmetrics/gwmetrics.go#L192-L218)).
    - The Prometheus histograms on the admin listener.
    - One access-log line. Bodies, headers and query strings are never logged.

## Release pipeline

<img class="diagram dark:sl-hidden" src="/halos/diagrams/lld-release-pipeline-light.svg" alt="Release pipeline in four rows: load, validate with guardrails, build the ring plus variant releases; render each harness for each OS, CheckRendered backstop, pack a content-addressed tar; sign the digest with ed25519 and optional cosign, push blobs and manifest, tag v<version> immutably; then build, sign and tag the ring pointer." width="760" />
<img class="diagram light:sl-hidden" src="/halos/diagrams/lld-release-pipeline-dark.svg" alt="Release pipeline in four rows: load, validate with guardrails, build the ring plus variant releases; render each harness for each OS, CheckRendered backstop, pack a content-addressed tar; sign the digest with ed25519 and optional cosign, push blobs and manifest, tag v<version> immutably; then build, sign and tag the ring pointer." width="760" />

`halo release publish --ring R --release-version V --key K` ([`cmd/halo/cmd_release.go:181-236`](https://github.com/dshakes/halos/blob/main/cmd/halo/cmd_release.go#L181-L236)):

1. **Load.** `policy.Load` reads `halos.yaml` and every `*.yaml` under the directory in sorted order, decoding strictly so unknown fields are errors ([`internal/policy/load.go:54-117`](https://github.com/dshakes/halos/blob/main/internal/policy/load.go#L54-L117)).
2. **Validate.** `loadValid` refuses to continue on any validation error ([`cmd/halo/root.go:184-198`](https://github.com/dshakes/halos/blob/main/cmd/halo/root.go#L184-L198)). `Org.Validate` runs the semantic checks and then the 13 `DefaultGuardrails` ([`internal/policy/validate.go:53-64`](https://github.com/dshakes/halos/blob/main/internal/policy/validate.go#L53-L64), [`internal/policy/guardrails.go:19-33`](https://github.com/dshakes/halos/blob/main/internal/policy/guardrails.go#L19-L33)), among them `guardNoBypass` ([`internal/policy/guardrails.go:41-62`](https://github.com/dshakes/halos/blob/main/internal/policy/guardrails.go#L41-L62)).
3. **Build ring.** `release.BuildRing` builds one release per variant of every running client-axis experiment that enrolls the ring, then the ring release itself. The ring release's manifest lists those experiments with their salt, weights and channels ([`internal/release/channels.go:24-59`](https://github.com/dshakes/halos/blob/main/internal/release/channels.go#L24-L59)).
4. **Render.** `release.Build` calls each enabled adapter's `Render` for darwin, linux and windows. Warnings land in the manifest; nothing is silently dropped ([`internal/release/release.go:110-189`](https://github.com/dshakes/halos/blob/main/internal/release/release.go#L110-L189)).
5. **Backstop.** `CheckRendered` parses every rendered JSON and TOML file and fails the build if any value is `bypassPermissions` or `danger-full-access`. It also runs per-harness checks ([`internal/release/check.go:17-73`](https://github.com/dshakes/halos/blob/main/internal/release/check.go#L17-L73)). It is called once per harness and OS ([`internal/release/release.go:160-162`](https://github.com/dshakes/halos/blob/main/internal/release/release.go#L160-L162)).
6. **Pack.** `pack` writes a deterministic USTAR tar (`manifest.json` plus `blobs/<sha256>`, epoch timestamps). The release digest is `sha256(tar)` ([`internal/release/release.go:191-223`](https://github.com/dshakes/halos/blob/main/internal/release/release.go#L191-L223)).
7. **Sign.** The signer is ed25519, or a `MultiSigner{ed25519, Cosign}` when `--cosign-key` or `--keyless` is set ([`cmd/halo/cmd_release.go:104-123`](https://github.com/dshakes/halos/blob/main/cmd/halo/cmd_release.go#L104-L123)). `publish` signs the tar digest before pushing anything. Co-signatures are stored as extra manifest annotations ([`internal/bundle/bundle.go:50-73`](https://github.com/dshakes/halos/blob/main/internal/bundle/bundle.go#L50-L73)). cosign runs as an external `cosign sign-blob`, without a transparency-log upload unless keyless ([`internal/bundle/sign.go:152-171`](https://github.com/dshakes/halos/blob/main/internal/bundle/sign.go#L152-L171)). halod verifies only ed25519, so a cosign-only signer is refused ([`internal/bundle/pointer.go:82-92`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L82-L92)).
8. **Push and tag.** Config and layer blobs are pushed if missing, and the OCI manifest is packed with the signature annotations. `v<version>` is tagged, and moving an existing tag is an error ([`internal/bundle/bundle.go:74-118`](https://github.com/dshakes/halos/blob/main/internal/bundle/bundle.go#L74-L118)). `PublishRing` publishes the variant channels before the ring, and runs every pointer preflight before any pointer moves ([`internal/bundle/channels.go:53-95`](https://github.com/dshakes/halos/blob/main/internal/bundle/channels.go#L53-L95)).
9. **Ring pointer.** `writePointer` builds `{org, ring, digest, manifest, seq, issuedAt, expiresAt}`:
   - `seq` is `max(current+1, unix now, recorded+1)`.
   - The time to live is 7 days.
   - The signature is ed25519 over `"halos.pointer.v1 " + sha256(payload)`.
   - It is pushed as its own artifact under `ring-<r>.pointer`, and the informational `ring-<r>` tag is moved ([`internal/bundle/pointer.go:21-58`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L21-L58), [`internal/bundle/pointer.go:239-300`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L239-L300)).

   Rollback is `PromoteRing` to an older version: a new pointer with a higher `seq` ([`internal/bundle/channels.go:97-141`](https://github.com/dshakes/halos/blob/main/internal/bundle/channels.go#L97-L141)).

Release binaries and images are signed separately. GoReleaser is configured for keyless cosign ([`.goreleaser.yaml:157-169`](https://github.com/dshakes/halos/blob/main/.goreleaser.yaml#L157-L169)), but no workflow in this repo runs that path; see [tech stack](/halos/architecture/tech-stack/#packaging-and-deploy).

## halod apply loop

<img class="diagram dark:sl-hidden" src="/halos/diagrams/lld-halod-loop-light.svg" alt="halod cycle in ten stages: restore and refresh the signed kill list, resolve the ring, verify the ring pointer, verify then fetch the release, pick the variant channel, merge toggles, check every target path, write atomically, remove stale files, save state and report; any verification failure keeps the last-good release." width="760" />
<img class="diagram light:sl-hidden" src="/halos/diagrams/lld-halod-loop-dark.svg" alt="halod cycle in ten stages: restore and refresh the signed kill list, resolve the ring, verify the ring pointer, verify then fetch the release, pick the variant channel, merge toggles, check every target path, write atomically, remove stale files, save state and report; any verification failure keeps the last-good release." width="760" />

`halod run` loops: `Once` every `interval` (default 15m), and with a kill switch, `PollKill` every `killSwitch.interval` (default 60s) in between. Both run on one goroutine, so `state.json` has a single writer ([`cmd/halod/main.go:163-190`](https://github.com/dshakes/halos/blob/main/cmd/halod/main.go#L163-L190), [`cmd/halod/config.go:68-69`](https://github.com/dshakes/halos/blob/main/cmd/halod/config.go#L68-L69), [`cmd/halod/config.go:227-236`](https://github.com/dshakes/halos/blob/main/cmd/halod/config.go#L227-L236)).

1. **Kill list.** `refreshKill` restores the persisted list, fetches and verifies the current one with the kill public key (not the release key), and persists it once accepted. A restart therefore cannot be fed an older envelope ([`cmd/halod/agent.go:320-335`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L320-L335), [`cmd/halod/keys.go:68-86`](https://github.com/dshakes/halos/blob/main/cmd/halod/keys.go#L68-L86)).
2. **Ring.** A fixed `ring` wins. Otherwise halod calls `GET ringEndpoint?user=&host=` with the device token, and validates the returned ring, subject and groups. If that fails, the last-known ring is used, except on the first run ([`cmd/halod/agent.go:212-223`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L212-L223), [`cmd/halod/agent.go:398-436`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L398-L436)).
3. **Pointer.** `bundle.PullRing` reads `ring-<r>.pointer` and checks its type and size and the ed25519 signature over the domain-separated statement. It then requires org = config, `seq` ≥ the last applied `seq`, the same digest when the `seq` is unchanged, and an unexpired pointer ([`internal/bundle/pointer.go:96-135`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L96-L135), [`internal/bundle/pointer.go:390-430`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L390-L430)). halod accepts any configured key that is not listed in `revokedKeys` ([`cmd/halod/keys.go:40-65`](https://github.com/dshakes/halos/blob/main/cmd/halod/keys.go#L40-L65)).
4. **Release.** `fetchRelease` fetches the manifest by the digest the pointer names, never through a tag. It verifies the signature over the layer digest before downloading, caps the layer size (256 MiB by default), and checks the digest while reading. It then requires release digest = pointer digest and release org = pointer org ([`internal/bundle/pointer.go:467-506`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L467-L506), [`internal/bundle/pointer.go:416-429`](https://github.com/dshakes/halos/blob/main/internal/bundle/pointer.go#L416-L429)).
5. **Variant.** If the ring release lists client-axis experiments, `selectVariant` computes the device's variant with `policy.Experiment.ResolveVariant`, the same hash the gateway uses. It skips experiments on the kill list and pulls the variant channel with the same pointer checks. If that channel fails, the whole cycle fails: falling back would silently move treatment devices to control ([`cmd/halod/agent.go:267-315`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L267-L315)).
6. **Toggles.** `activeToggles` evaluates the client toggles in the signed manifest against the ring, subject and groups, minus the killed ones. `withToggles` merges their per-harness fragments ([`cmd/halod/toggles.go:27-96`](https://github.com/dshakes/halos/blob/main/cmd/halod/toggles.go#L27-L96)).
7. **Check targets.** For every file, `checkTarget` requires ([`cmd/halod/agent.go:536-544`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L536-L544), [`cmd/halod/paths.go:65-83`](https://github.com/dshakes/halos/blob/main/cmd/halod/paths.go#L65-L83), [`cmd/halod/paths.go:119-141`](https://github.com/dshakes/halos/blob/main/cmd/halod/paths.go#L119-L141)):
   - a path inside the adapter's managed directories or files
   - mode `0644` or lower
   - every existing parent root-owned, not group- or world-writable, and not a planted symlink

   A file that fails is refused and the rest still apply.
8. **Write.** `ensureFile` writes only when the content hash differs, and flags drift when the release did not change. `fsutil.WriteAtomic` writes a temp file, fsyncs it and renames it over the target ([`cmd/halod/agent.go:548-582`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L548-L582), [`internal/fsutil/fsutil.go:15-59`](https://github.com/dshakes/halos/blob/main/internal/fsutil/fsutil.go#L15-L59)).
9. **Stale files.** Files the previous release owned that this one does not ship are removed, but only inside managed locations ([`cmd/halod/agent.go:503-519`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L503-L519)).
10. **State and report.** `state.json` records the digest, owned files, pointer marks, installs and kill list. The status is printed as one JSON line and POSTed to `reportURL` with the device token ([`cmd/halod/agent.go:520-531`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L520-L531), [`cmd/halod/agent.go:597-636`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L597-L636)).

Between pulls, `PollKill` reacts to kill-list changes without a registry round trip ([`cmd/halod/agent.go:352-394`](https://github.com/dshakes/halos/blob/main/cmd/halod/agent.go#L352-L394)):

- If the device's experiment was just killed, halod applies the cached, already-verified ring release.
- If the experiment was unkilled, or toggle kills changed while the device is on a variant, halod runs a full cycle.

## Controller loop

<img class="diagram dark:sl-hidden" src="/halos/diagrams/lld-controller-loop-light.svg" alt="Controller tick in eleven stages: load policy, skip rollout-owned experiments, hold killed experiments, read ClickHouse evidence, guardrails (rollback), budgets (expired), sample floor (continue), primary metric (promote or rollback), act on rollback with a gateway-evidence-only kill plus pause PR, conclude PR on promote or expiry, then evaluate rollouts from hash-chained state." width="760" />
<img class="diagram light:sl-hidden" src="/halos/diagrams/lld-controller-loop-dark.svg" alt="Controller tick in eleven stages: load policy, skip rollout-owned experiments, hold killed experiments, read ClickHouse evidence, guardrails (rollback), budgets (expired), sample floor (continue), primary metric (promote or rollback), act on rollback with a gateway-evidence-only kill plus pause PR, conclude PR on promote or expiry, then evaluate rollouts from hash-chained state." width="760" />

`halo-server --controller` runs the loop every `--interval` (5m by default, at least 1m) ([`cmd/halo-server/main.go:255-272`](https://github.com/dshakes/halos/blob/main/cmd/halo-server/main.go#L255-L272)). After a failed tick it retries sooner, from 15 s up to the interval ([`internal/controller/controller.go:356-376`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L356-L376)). `halo controller run` runs the same loop.

1. **Tick.** One tick has a 2-minute budget. It loads the served policy and walks the running experiments by name ([`internal/controller/controller.go:85-125`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L85-L125)).
2. **Rollout-owned.** An experiment that backs an active Rollout is skipped here; the rollout drives it ([`internal/controller/rollouts.go:61-70`](https://github.com/dshakes/halos/blob/main/internal/controller/rollouts.go#L61-L70)).
3. **Killed.** A killed running experiment is not evaluated, because its evidence is all control. Humans are told once ([`internal/controller/controller.go:127-138`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L127-L138), [`internal/controller/controller.go:310-322`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L310-L322)).
4. **Evidence.** `promote.ClickHouse` reads `halo_metrics` over ClickHouse's HTTP interface with server-side bound parameters ([`internal/promote/source.go:38-136`](https://github.com/dshakes/halos/blob/main/internal/promote/source.go#L38-L136)). `Samples` returns one value per (variant, unit) and the evidence source of the row ([`internal/promote/source.go:219-253`](https://github.com/dshakes/halos/blob/main/internal/promote/source.go#L219-L253)).
5. **Guardrails.** Each guardrail is tested with `stats.SeqGuardrail`, an always-valid mSPRT confidence sequence, at alpha divided by the number of guardrails. Any failure is a `rollback` ([`internal/promote/promote.go:117-137`](https://github.com/dshakes/halos/blob/main/internal/promote/promote.go#L117-L137), [`internal/stats/guardrail.go:37-71`](https://github.com/dshakes/halos/blob/main/internal/stats/guardrail.go#L37-L71)).
6. **Budgets.** Exceeding `maxDays` or `maxSpendUSD` is `expired` ([`internal/promote/promote.go:139-146`](https://github.com/dshakes/halos/blob/main/internal/promote/promote.go#L139-L146)).
7. **Sample floor.** Fewer than `minSamples` per arm is `continue` ([`internal/promote/promote.go:148-152`](https://github.com/dshakes/halos/blob/main/internal/promote/promote.go#L148-L152)).
8. **Primary.** A significant regression is `rollback`. A significant improvement with every guardrail passing is `promote` ([`internal/promote/promote.go:154-171`](https://github.com/dshakes/halos/blob/main/internal/promote/promote.go#L154-L171)).
9. **Rollback.** The kill switch is tripped first, but only when the deciding evidence is gateway-sourced, because CLI and eval telemetry can be forged or are opinion ([`internal/controller/controller.go:182-213`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L182-L213)). The kill appends to `killswitch.jsonl` with an fsync ([`internal/controller/killstore.go:112-149`](https://github.com/dshakes/halos/blob/main/internal/controller/killstore.go#L112-L149)). Every gateway sees it at its next kill-list poll (10 s by default). The controller then opens a pause PR and notifies, even if the kill failed ([`internal/controller/controller.go:215-232`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L215-L232)).
10. **Promote or expired.** The controller opens a PR concluding the experiment, then notifies ([`internal/controller/controller.go:234-250`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L234-L250)). PRs are opened by `GitWriter`, which commits on a new branch in a temporary worktree, pushes it and runs `gh pr create` ([`internal/controller/writer.go:31-58`](https://github.com/dshakes/halos/blob/main/internal/controller/writer.go#L31-L58), [`internal/promote/pr.go:311-328`](https://github.com/dshakes/halos/blob/main/internal/promote/pr.go#L311-L328)). Nothing merges. Each action is recorded in `controller-state.jsonl`, so it happens at most once per experiment run ([`internal/controller/controller.go:252-268`](https://github.com/dshakes/halos/blob/main/internal/controller/controller.go#L252-L268)).
11. **Rollouts.** For each Rollout ([`internal/controller/rollouts.go:42-136`](https://github.com/dshakes/halos/blob/main/internal/controller/rollouts.go#L42-L136)):
    - its state is loaded from `rollouts/<name>.json`, and a file whose hash chain does not verify is never acted on ([`internal/rollout/state.go:154-186`](https://github.com/dshakes/halos/blob/main/internal/rollout/state.go#L154-L186))
    - evidence and scorecards are gathered, and `rollout.Evaluate` decides `advance`, `hold`, `rollback`, `pause` or `complete` ([`internal/rollout/rollout.go:84-151`](https://github.com/dshakes/halos/blob/main/internal/rollout/rollout.go#L84-L151))

    `rollback` and `pause` halt the rollout. A traffic-axis rollback on gateway evidence also trips the kill switch. Both then open a PR ([`internal/controller/rollouts.go:138-181`](https://github.com/dshakes/halos/blob/main/internal/controller/rollouts.go#L138-L181)). `advance` and `complete` only open a PR ([`internal/controller/rollouts.go:183-195`](https://github.com/dshakes/halos/blob/main/internal/controller/rollouts.go#L183-L195)).

:::note[UNVERIFIED: GitHub PRs]
`GHOpener` is marked UNVERIFIED against a real GitHub in its own source. Its tests use real git and a recording `gh` ([`internal/promote/pr.go:285-291`](https://github.com/dshakes/halos/blob/main/internal/promote/pr.go#L285-L291)).
:::
