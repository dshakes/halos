# Harness facts (verified 2026-09-30)

Every claim was read from the cited source. Claims marked **[UAT]** were observed
with the real CLI at the acme-corp pins (claude-code 2.1.280, codex 0.99.0 (was 0.58.0),
gemini-cli 0.34.0 (was 0.12.0), copilot 1.0.90) by `make uat-clis` (test/uat, CLI-REPORT.md);
they override the docs where they disagree.

## Claude Code
- **[UAT]** Managed `model: sonnet` is resolved by the CLI before sending (2.1.280 sends `claude-sonnet-5`; `opus` -> `claude-opus-5-5`), so a gateway that allowlists policy aliases rejects it. `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL=<alias>` makes it send the alias (it then prints a harmless `[claude-code:unrecognized_model]` line); the adapter sets these for every Claude alias the gateway routes.
- **[UAT]** A model outside `availableModels` with `enforceAvailableModels` is never sent, but `--model` is dropped **silently** (no notice, not even in `--debug`) and the CLI uses its tier default as a built-in ID (`claude-opus-5-5[1m]` on 2.1.280), not the managed `model`; `--model default` does the same. That path ignores `ANTHROPIC_DEFAULT_*_MODEL`, `ANTHROPIC_DEFAULT_MODEL` and `ANTHROPIC_MODEL` (process or managed env); `CLAUDE_CODE_NO_MODEL_FALLBACK` only governs Fable substitution; dropping `opus` from `availableModels` just moves it to `claude-sonnet-5`. No setting makes `--model` refuse locally (only the interactive `/model` says "Your organization restricts model selection"). **`modelOverrides` is applied to it** ("policy-mapped"): `{"claude-opus-5-5": "opus"}` sends the fallback as `opus` (the `[1m]` suffix is stripped before lookup). The adapter renders `modelOverrides` built-in ID -> alias for each Claude alias the gateway routes (IDs verified on 2.1.280: `claude-opus-5-5`, `claude-sonnet-5`, `claude-haiku-4-5-20251001`). A gateway refusal (400 since G5) is not retried; a 403 was retried 11 times.
- **[UAT]** `requiredMinimumVersion`/`requiredMaximumVersion` stop `claude -p` at startup ("...older than the minimum version required by your organization"); `claude --version` is not gated. `permissions.deny` `Read(./.env)` returns "File is in a directory that is denied by your permission settings" to the model. `allowManagedMcpServersOnly` hides a user-added server from `claude mcp list` and it is never contacted. OTLP resource attributes from `OTEL_RESOURCE_ATTRIBUTES` in managed `env` arrive on logs and metrics.
- Bypass lock (docs read 2026-10-27, https://code.claude.com/docs/en/settings-reference#permissions-disablebypasspermissionsmode): the key is `permissions.disableBypassPermissionsMode` (`"disable"`), one of the `permissions` object's fields (`allow`, `ask`, `deny`, `additionalDirectories`, `blockReadsOutsideWorkingDirectories`, `defaultMode`, `disableBypassPermissionsMode`, `disableAutoMode`); the reference documents no top-level form. With it Claude Code rejects `--dangerously-skip-permissions` and ignores an agent's `permissionMode: bypassPermissions`. Halos rendered it at the top level before v0.4; the release check now fails a top-level key.
- Extension surfaces (docs read 2026-10-21, not UAT; sources https://code.claude.com/docs/en/settings-reference and https://code.claude.com/docs/en/permissions): managed-only keys `strictKnownMarketplaces` (allowlist; entries `{source: github|git|url|hostPattern|..., repo|url|ref|hostPattern}`; an empty array blocks every marketplace, including Anthropic's) and `blockedMarketplaces` (same entry shapes). `enabledPlugins` is `{"plugin@marketplace": bool}`; a managed `false` blocks install at every scope. `strictPluginOnlyCustomization` is `true` or an array of `skills|agents|hooks|mcp` (user and project sources blocked; plugins and managed settings still load). `outputStyle` is a name; `statusLine` is `{type: "command", command, padding?, refreshInterval?}`; `forceLoginMethod` is `claudeai|console|gateway`. Skills and subagents are denied with permission rules `Skill(skill:NAME)` and `Agent(NAME)`. `skillOverrides` is not used: it does not apply to plugin skills.

The adapter warns for 0.77-0.98; the example pins are 0.99.0. - **[UAT]** codex 0.99.0 offers `exec_command {cmd}` instead of `shell {command[]}`, and `codex exec --json` emits no item for a failed `exec_command`, so the eval driver cannot count those tool errors.
- **[UAT]** `codex exec` in a non-git workdir exits 1 "Not inside a trusted directory" without `--skip-git-repo-check` (the eval driver passes it). The `workspace-write` sandbox is Landlock: on a kernel without it (Docker Desktop linuxkit 6.10.14) every shell call exits 101 "error running landlock".

- `codex exec`: `--json`, `--sandbox/-s`, `-m/--model`, `--skip-git-repo-check`, `-` reads prompt from stdin (X). JSONL events `thread.started`, `turn.completed{usage.input_tokens,output_tokens}`, `turn.failed{error.message}`, `error`, `item.completed{item.type=command_execution, exit_code}` (exec_events.rs).
- npm package `@openai/codex` (registry latest 0.159.2).
- Extension surfaces (docs read 2026-10-21, not UAT; M and R): requirements.toml `[marketplaces]` with `restrict_to_allowed_sources = true` and `[marketplaces.allowed_sources.<name>]` rules `{source = "git", url, ref?}`, `{source = "host_pattern", host_pattern}`, `{source = "local", path}` (M). ## OpenCode (verified 2026-10-21)
Sources: C = https://opencode.ai/docs/config/, P = https://opencode.ai/docs/permissions/, M = https://opencode.ai/docs/mcp-servers/, E = https://opencode.ai/docs/enterprise/, S = https://opencode.ai/config.json (JSON Schema), B = the `opencode-ai` 1.19.3 darwin-arm64 binary (npm), source strings read from it. **[RUN]** = observed by running that 1.19.3 binary in this change (a recording HTTP server as the model endpoint, `opencode debug config|agent`, `opencode mcp list|models`); `OPENCODE_TEST_MANAGED_CONFIG_DIR` points the managed directory at a scratch dir, which is how managed behaviour was exercised without root. These are not part of `make uat-clis`.

- Managed config (highest priority, users cannot override): `opencode.json` or `opencode.jsonc` in `/Library/Application Support/opencode/` (macOS), `/etc/opencode/` (Linux), `%ProgramData%\opencode` (Windows) (C; B: `case"darwin":return"/Library/Application Support/opencode";case"win32":...join(ProgramData||"C:\\ProgramData","opencode");default:return"/etc/opencode"`). macOS MDM: preference domain `ai.opencode.managed` (`.mobileconfig`; plist keys mirror opencode.json); not rendered. Precedence: remote `.well-known/opencode` < global `~/.config/opencode/opencode.json` < `OPENCODE_CONFIG` < project `opencode.json` < `.opencode/` < `OPENCODE_CONFIG_CONTENT` < managed files < managed preferences (C).
- **[RUN]** A managed `model`, `share` and `enabled_providers` replace the project config's values, and a managed `permission` replaces a project `bash: allow`. A managed `mcp.<name>: {"enabled": false}` disables a user-defined server (`opencode mcp list`: `foo disabled`), while an unlisted user server still starts. **`OPENCODE_PERMISSION` (a user environment variable) overrides the managed `permission` block**, in the resolved config and in the agent's ruleset (`debug agent build`): the adapter warns, and `--auto` ("auto-approve permissions that are not explicitly denied") is likewise not blockable. Explicit `deny` rules still hold under `--auto` (P).
- Two schemas exist. S lists `permission`, `provider`, `agent` and flat `mcp.<name>` as deprecated in favour of `permissions`, `providers`, `agents`, `mcp.servers`, but **1.19.3 (npm `latest`) reads and resolves the v1 keys** (**[RUN]**), and C still documents them; the adapter renders v1. The docs page names the shell permission `shell`; 1.19.3's tool id and ruleset key is `bash` (**[RUN]**: `debug agent build` lists `bash`; the binary asks `permission:"bash"` and has no `permission:"shell"`, so a `shell` rule is accepted by the schema but never consulted), so the adapter renders `bash`. Re-check both when a 2.x reaches `latest`.
- Permissions (P): per-tool `allow|ask|deny`, either a string or `{pattern: action}`, last matching rule wins, `*` matches any characters including `/`. Keys rendered: `bash`, `read`, `edit` (covers edit/write/patch), `glob`, `grep`, `task`, `external_directory`. Defaults are permissive (`allow`; `external_directory` and `doom_loop` ask; `.env` reads ask). **[RUN]** `bash` patterns are matched against the parsed command, so `Bash(go test:*)` needs both `go test` and `go test *`. `read`/`edit` patterns are matched against the path relative to the worktree (B: `patterns:[z.relative(c.worktree,h)]`), so a home or absolute path is only visible to `external_directory` (P: `~/` and `$HOME` expand there), and `**/x` needs an added root-level `x`. The adapter starts `bash` and `edit` from `"*": "ask"` once they have a rule (Claude Code's behaviour for an unlisted command or edit) and orders each object allow, ask, deny so deny wins; it never renders a global allow (`permission: "allow"` or `"*": "allow"`), which `internal/release/check.go` rejects.
- MCP (M, S): `mcp.<name>` is `{type: "local", command: [..], environment, enabled}` or `{type: "remote", url, headers, oauth, enabled}`. There is **no allowlist and no managed-only switch**; `mcp.denied` can only disable by name.
- Models and gateway (C, S, **[RUN]**): `provider.<id>` is `{npm, name, options: {baseURL, apiKey, headers, ...}, models: {<id>: {name}}}`; the model is `<provider>/<model>`; `{env:VAR}` and `{file:path}` substitute in values. `enabled_providers` is an allowlist (C); with a managed `["halos"]`, `opencode models` lists only `halos/*` although the project config defines another provider. `npm: "@ai-sdk/anthropic"` posts `POST <baseURL>/messages` (`/v1/messages` with `baseURL: <gw>/v1`) with `x-api-key` and `anthropic-version`; `@ai-sdk/openai` posts `POST <baseURL>/responses`; `@ai-sdk/openai-compatible` posts `/chat/completions` (not a Halos gateway wire, so not used). The body carries the model name as written under `models`. `options.headers` are sent on every request. The AI SDK package is fetched from npm at first use (E: private registries work through `.npmrc`).
- User-Agent (**[RUN]**, both wires): `opencode/1.19.3 ai-sdk/provider-utils/4.0.46 runtime/bun/1.3.14`; Meta.UAPrefixes `opencode/`. Session headers sent on every model call: `x-session-id`, `x-opencode-session-id`, `x-session-affinity` (all the same `ses_...` id); Halos does not read them.
- Instructions (C): `instructions: ["<abs path or glob>", ...]`. **[RUN]** an absolute path in the managed file reaches the main request's system prompt (the small title request does not carry it).
- `autoupdate: false` stops self-update (C); rendered when the profile pins a version, since halod installs the pin. npm package `opencode-ai` (latest 1.19.3); `opencode --version` prints `1.19.3`.
- Headless: `opencode run "<message>"`; flags `--auto` (dangerous, never passed), `--attach`, `--log-level`.
- Not rendered, warned: `hooks.*` (OpenCode extends through plugins, which run arbitrary code), `telemetry.*` (S has no OTLP key: `experimental.openTelemetry` only switches on AI SDK spans (B), and the exporter is configured by `OTEL_EXPORTER_OTLP_*` environment, which a managed file cannot set), `env`, `permissions.mode`, `permissions.sandbox` (no sandbox in S; egress and protected paths: see "Sandbox and egress" below), `permissions.disableBypass`, `mcp.managedOnly`, `gateway.auth.helperCommand` (the credential is `{env:HALO_GATEWAY_TOKEN}`).

## MCP registry (ADR-0029)

Docs read 2026-10-27 (not UAT, no CLI was run against these renders):

- Claude Code (https://code.claude.com/docs/en/mcp, https://code.claude.com/docs/en/permissions): `managed-mcp.json` remote entries take `oauth.clientId`, `oauth.scopes` (one space-separated string; overrides discovered scopes), `oauth.authServerMetadataUrl` and `headersHelper` (a shell command printing a JSON object of headers, run fresh on every connection; for managed servers with the user's environment). A permission deny rule `mcp__<server>__<tool>` removes a tool; deny always wins over allow, so there is no per-server tool allowlist. No documented setting for an org-hosted Client ID Metadata Document or Enterprise-Managed Authorization.
- Codex (S above, `RawMcpServerConfig`, `additionalProperties: false`): `enabled_tools`, `disabled_tools`, `http_headers`, `env_http_headers`, `bearer_token_env_var`, plus `oauth`, `scopes`, `oauth_resource`, `http_headers_helper` and `auth`. The adapter renders the tool lists only: an mcp_servers key a pinned binary does not know makes codex refuse to start, and the auth keys' first release is unverified.
- Gemini CLI (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/tools/mcp-server.md): per-server `includeTools` / `excludeTools` (exclude wins; across settings sources inclusions intersect and exclusions union) and `oauth` `{enabled, clientId, clientSecret, issuer, authorizationUrl, tokenUrl, scopes, audiences, redirectUri}`; tokens in `~/.gemini/mcp-oauth-tokens.json`. Headers are static: no helper command.
- Copilot CLI (https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings): managed settings hold `allowedMcpServers` / `deniedMcpServers` only (one matcher per entry: `serverName`, `serverUrl` with wildcards, `serverCommand`; the allowlist is intersected across sources; deny wins; first-party servers cannot be denied). No managed key for tool filtering or server credentials.
- OpenCode (M, S): remote entries take `oauth: {clientId, clientSecret, scope}` or `false`, and `headers` with `{env:VAR}`; MCP tools are named `<server>_<tool>` and `tools.<glob>: false` disables them. S marks `tools` (and `permission`) deprecated; the adapter keeps `tools` because M documents it and the pinned 1.19.3 reads it. How a later `true` glob overrides an earlier `false` is not documented, so allowlists warn.
- Cursor CLI: no root-owned MCP file (above); everything warns.
- Official MCP Registry: server.json schema https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json (`packages[].registryType|identifier|version|transport|packageArguments|fileSha256`, `remotes[].type|url|headers`); `GET https://registry.modelcontextprotocol.io/v0/servers/<url-escaped name>/versions/latest` answers `{"server": <server.json>, "_meta": ...}` (fetched 2026-10-27).
- User configs halod scans for drift: `~/.claude.json` (`mcpServers`, `projects.<path>.mcpServers`), `~/.codex/config.toml` (`mcp_servers`), `~/.gemini/settings.json`, `~/.copilot/mcp-config.json`, `~/.cursor/mcp.json` (`mcpServers`), `~/.config/opencode/opencode.json` (`mcp`).
- UNVERIFIED: Codex `auth = "ema_auth"` semantics; any CLI's support for Client ID Metadata Documents or Enterprise-Managed Authorization; whether each CLI accepts the rendered tool and oauth keys at the pinned versions (goldens only).

- GitHub webhooks: `X-Hub-Signature-256: sha256=<hex HMAC-SHA256(secret, raw body)>`, compared in constant time; the documented test vector (secret `It's a Secret to Everybody`, body `Hello, World!`) is in `TestVerifySignature` (GW).
- Actions runs: `GET /repos/{o}/{r}/actions/runs` (`created`, `status`, `per_page`), `POST .../actions/runs/{id}/cancel`, and `PUT .../actions/workflows/{workflow_id}/disable|enable`, where `workflow_id` may be the file name (GR, GF).
- Copilot cloud agent: the only repository file it reads is `.github/workflows/copilot-setup-steps.yml`; job `copilot-setup-steps` honors only `steps`, `permissions`, `runs-on`, `services`, `snapshot` and `timeout-minutes` (at most 59); Copilot gets its own token (GE). Firewall: org setting Enabled/Disabled/Let repositories decide, recommended allowlist, custom allowlist (domains match subdomains), set in the console (GI). `GET /repos/{o}/{r}/copilot/cloud-agent/configuration` (public preview, API version 2026-03-10) returns `is_firewall_enabled`, `is_firewall_recommended_allowlist_enabled`, `custom_allowlist`; no write endpoint is documented (GC). Repository access (all / selected / none) is an org setting (GO).
- Claude Code GitHub Action: inputs `anthropic_api_key`, `claude_code_oauth_token`, `claude_args` (`--model`, `--max-turns`, `--allowedTools`), `settings` (JSON); `id-token: write` is needed for the GitHub App token exchange; v1 tags are moving, so the rendered workflow pins the v1.0.264 commit (CA). The action refuses to start without `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` or federation ids (CV), so identity: workload passes the Halos gateway credential as `anthropic_api_key` (halo-proxy reads `x-api-key`, internal/identity).
- Claude Code cloud sessions: an organization policy `allow_remote_sessions` (Owner, claude.ai admin settings); each cloud environment has one network access level None / Trusted / Full / Custom, and there is no organization-wide allowlist or server-managed setting for it (CW, CE). - Cursor Cloud Agents API: `GET /v1/agents` lists the key owner's agents (newest first, `nextCursor` omitted at the end); agent `status` is ACTIVE / IDLE / ARCHIVED; `POST /v1/agents/{id}/runs/{runId}/cancel` (409 `run_not_cancellable` when not active); `POST /v1/agents/{id}/archive` is reversible (unarchive); `GET /v1/agents/{id}/usage` reports tokens, not cost; Basic or Bearer auth (UA).

## Sandbox and egress (docs read 2026-10-27, not UAT; ADR-0032)
Sources: CS = https://code.claude.com/docs/en/sandboxing, CR = https://code.claude.com/docs/en/settings-reference (sandbox settings, path prefixes), CP = https://code.claude.com/docs/en/permissions; OM = https://learn.chatgpt.com/docs/enterprise/managed-configuration, OS = https://raw.githubusercontent.com/openai/codex/main/codex-rs/core/config.schema.json, OQ = https://raw.githubusercontent.com/openai/codex/main/codex-rs/config/src/config_requirements.rs; GS = https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/sandbox.md, GC = .../docs/reference/configuration.md; HM = https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings; PP = https://opencode.ai/docs/permissions/; US = https://cursor.com/docs/reference/sandbox.md, UC = https://cursor.com/docs/cli/reference/configuration.md.

- **Claude Code** (CS, CR, CP): `sandbox.network.allowedDomains` (start empty), `deniedDomains` (refused in every permission mode), `allowManagedDomainsOnly` (managed only: other hosts refused without a prompt, only managed allow entries count). Wildcards: leading `*.` and bare `*` (2.1.186+). `sandbox.filesystem.allowWrite|denyWrite|denyRead|allowRead`: `/` absolute, `~/` home, `./` or none = project root (project settings) or `~/.claude` (user settings); managed-settings resolution of relative paths is not documented, so relative protected paths are rendered only as `Read`/`Edit` rules. The sandbox covers Bash only: Read/Edit/WebFetch follow permission rules, so deny-by-default cannot be expressed for WebFetch (deny wins over allow); unlisted hosts ask.
- **Codex** (OM, OS, OQ): requirements.toml `[experimental_network]` `enabled`, `managed_allowed_domains_only`, `[experimental_network.domains] "<host>" = "allow"|"deny"` (deny wins; `*.x` subdomains only, `**.x` apex too); documented as experimental and "does not filter web search, apps, MCP servers or Codex service requests"; it does not grant network when the sandbox keeps `network_access` off. `[permissions.filesystem] deny_read` (absolute or `~`; `./` refused; on native Windows direct file tools only). In source `ConfigRequirementsToml` has no `deny_unknown_fields`, `network_proxy` is the new name with `experimental_network` an alias ("policy publishers must continue using [experimental_network]"). The minimum codex version honoring either table is not documented. managed_config.toml `[sandbox_workspace_write] writable_roots` (AbsolutePathBuf), `network_access` (default false).
- **Gemini CLI** (GS, GC): `tools.sandbox` (bool, profile path or command) in settings; precedence `--sandbox`/`-s` > `GEMINI_SANDBOX` > settings. macOS Seatbelt default profile `permissive-open` (writes confined to the project, network allowed); Linux/Windows need Docker/Podman (or experimental windows-native/lxc/runsc). `tools.sandboxAllowedPaths`, `tools.sandboxNetworkAccess` (bool) and `security.toolSandboxing` exist; their scope relative to `tools.sandbox` is not documented, so they are not rendered. No domain lists, no protected-path list.
- **Copilot CLI** (HM): managed `sandbox` {`enabled`, `failIfUnavailable`, `allowBypass`, `addCurrentWorkingDirectory`, `sandboxMcpServers`, `sandboxLspServers`, `userPolicy.filesystem` {`readwritePaths`, `readonlyPaths`, `deniedPaths` ("should be absolute")}, `userPolicy.network` {`allowOutbound`, `allowLocalNetwork`, `allowedHosts` (non-empty blocks the rest; `*.x` subdomains only, `*` all), `blockedHosts` (wins; blocks subdomains too), `proxy`}}; managed values are minimums. Minimum Copilot CLI 1.0.93; older clients are blocked from Copilot while the key is set, so the adapter renders nothing for an older pin. On Windows the sandbox relies on programs honoring proxy settings. Managed `permissions.deny|ask|allow` with `Domain(...)` exist but any managed rule makes every unmatched operation ask, so they are not rendered.
- **OpenCode** (PP): `permission.webfetch` takes one action (`allow|ask|deny`) for every URL in v1 (no URL patterns). No sandbox key in the schema.
- **Cursor** (US, UC): `sandbox.json` `type` (`workspace_readwrite` | `workspace_readonly` | `insecure_none`), `additionalReadwritePaths`, `networkPolicy {default (deny), allow, deny}` (deny wins; `*.x` includes the apex; CIDR allowed), at `~/.cursor/sandbox.json` (per user) and `<workspace>/.cursor/sandbox.json`; team-admin policy from the dashboard layers on top. No system-wide location, so nothing is rendered; `~/.cursor/sandbox.json` `type = "insecure_none"` is a posture finding.
- UNVERIFIED (not exercised with the real CLIs): Codex `[experimental_network]` and `deny_read` at the pinned 0.99.0; Copilot `deniedPaths` `~/` expansion and whether its URL fetches use the sandbox proxy; Gemini `tools.sandbox: true` from the macOS system settings file at 0.34.0; Claude Code relative managed `sandbox.filesystem` paths; OpenCode 1.19.3 honoring a managed `webfetch`.
